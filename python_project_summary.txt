2. DETAILED FILE ANATOMY: admin_dashboard.py (Streamlit Control Room)
--------------------------------------------------------------------------------
This Python script serves as a high-fidelity administrative monitoring GUI.

A. Libraries Used and Purpose:
   - streamlit (st): Renders the overall Obsidian dark-mode dashboard canvas, 
     responsive grids, titles, and structural borders.
   - pandas (pd): Sanitizes dynamic JSON Firebase records into clean data tables, 
     performs text transformations, and aggregates demographic counts.
   - requests / json: Communicates securely with the Firebase Realtime Database 
     via HTTP REST API endpoints using secure authorization tokens.
   - plotly.express (px): Renders vector-based plots for Pune Route Corridor 
     demand and passenger service breakdowns.
   - matplotlib.pyplot (plt): Renders highly customized multi-dimensional 
     statistical graphics.
   - time: Handles system pacing and auto-refresh throttle intervals.

B. Key Features Implemented:
   - Obsidian Glassmorphic Stylesheet: Injected custom raw CSS styling directly 
     into Streamlit to enforce the 'Outfit' Google typography, set transparent 
      obsidian backdrops, and enable glowing border transition animations.
   - Decoupled Dual-Layer Auto-Refresh:
       1. Browser Telemetry Layer: Injected Javascript that silently polls 
          Firebase stats every 500ms to update speedometer needle dials, safety 
          badges, and progress tracks instantly with ZERO page reloading blinks.
       2. Streamlit Python Layer: Runs a background loop every 5 seconds 
          (time.sleep(5) + st.rerun()) to pull fresh ticket sales and redraw 
          Plotly/Matplotlib charts smoothly.
   - Glow-Enhanced SVG Speedometer: Features a custom vector dial with circular 
     linear gradients and a Gaussian blur glow filter (#gauge-glow) that changes 
     color (Green -> Orange -> Red) depending on bus occupancy levels.
   - Dynamic Mini Progress Tracks: Renders real-time capacity progress indicators 
     and calculates exit-to-entry inflow ratios dynamically as scans occur.
   - Matplotlib Dark Mode Visualizations:
       1. Hourly Commuter Shaded Area Chart: Plots daily passenger inflow vs. 
          outflow timeline cycles with smooth alpha-transparent shaded area fills.
       2. Corridor Demand Scatter Bubble Plot: A 3D scatter chart correlating 
          route booking count (X) vs. average ticket fare (Y), where the radius 
          of each bubble is directly proportional to aggregate revenue generated.

3. DETAILED FILE ANATOMY: esp32camtestpython.py (QR Turnstile Node)
--------------------------------------------------------------------------------
This Python script processes the real-time optical feed for turnstile validation.

A. Libraries Used and Purpose:
   - cv2 (OpenCV): Captures network frames, decodes compressed JPEG formats, 
     overlays HUD scan details, and manages keyboard events.
   - numpy (np): Converts raw HTTP frame byte arrays into structured uint8 
     NumPy matrices so OpenCV can interpret the image.
   - pyzbar.pyzbar: Uses advanced position-detection square tracking to locate 
     and extract raw alphanumeric payloads from QR codes in real-time.
   - urllib.request: Downloads continuous snapshot feeds (/cam-hi.jpg) from the 
     onboard ESP32-CAM microcontroller local Wi-Fi IP address.
   - requests / time: Securely writes QR scans and time metadata to Firebase.

B. Key Features Implemented:
   - Wireless Stream Reconstruction: Downloads and decodes network frames 
     wirelessly to enable physical placement of the ESP32 turnstile node.
   - Software Debouncing: Compares the scanned QR code in the current frame 
     against the previous frame (prev == pres). It ignores duplicates, ensuring 
     a passenger's ticket is only billed ONCE even if held in front of the 
     camera for several seconds.
   - Live HUD Overlay: Injects active text feedback onto the live feed.

4. HIGH-YIELD EXAMINER / VIVA QUESTIONS & ANSWER CHEAT SHEET
--------------------------------------------------------------------------------

Q1: Why did you choose Streamlit instead of standard Tkinter for your Python GUI?
A1: "Streamlit allows us to develop modern, responsive web applications entirely 
     in Python. It supports advanced layout grids, handles concurrent sessions, 
     and allows us to inject custom CSS stylesheets for a state-of-the-art 
     obsidian glassmorphic dark-mode look that aligns with our web portal."

Q2: How did you implement real-time updates without making the page blink constantly?
A2: "We engineered a decoupled dual-layer refresh system. We bypassed Python's 
     heavy thread re-runs for telemetry data by injecting custom client-side 
     JavaScript. The browser silently polls Firebase every 500ms and updates 
     the HTML DOM directly, enabling fluid, blink-free dial animations. Heavy 
     Plotly/Matplotlib charts re-render via a native Python loop every 5 seconds."

Q3: What is unique about your Matplotlib charts compared to default plots?
A3: "Standard Matplotlib plots have solid gray backgrounds and rigid boxes. We 
     completely customized them for dark mode by setting the figures and axes 
     to transparent (ax.set_facecolor('none')), drawing tick labels in clean 
     slate grays (#94a3b8), removing top and right boundaries, and adding 
     translucent micro-gridlines. We also engineered a multidimensional 
     bubble scatter plot where bubble size correlates directly with revenue."

Q4: What is software debouncing and why is it critical in your turnstile script?
A4: "In computer vision, a camera captures 30 frames per second. If a passenger 
     holds a QR code in front of the camera, a simple script would scan and bill 
     their ticket 30 times in one second. We implemented software debouncing 
     using state tracking variables (prev & pres) to compare frames. A ticket 
     is only scanned once; it will not scan again until a new payload is read."

Q5: Why did you use NumPy in your hardware camera script?
A5: "The ESP32-CAM streams the image as raw binary bytes over HTTP. Python cannot 
     render raw bytes. We used NumPy's high-performance 1D uint8 array structures 
     to pack these bytes, allowing OpenCV's cv2.imdecode to instantly parse them 
     into standard 3D BGR image arrays for display and optical decoding."
